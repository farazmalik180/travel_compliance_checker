# Experiments Deviations Log

This document records all methodological, configuration, and execution deviations from initial pre-registration specifications, including root causes, impact assessments, and corrective actions.

---

### Deviation 1: Dev Pilot Run 1 JSON Truncation and Fallback Inflation
* **Date:** 2026-10-29
* **Affected Artifacts:** `experiments/results/pilot_raw_checkpoint_run1_truncated.jsonl`, `run_manifest_run1_truncated.json`, `pilot_sampled_traces_run1_truncated.json`
* **Root Cause:**
  The LLM runner was configured with `max_tokens = 512`. Because `openai/gpt-oss-120b` generates hidden reasoning tokens (averaging 160–580 tokens) before outputting completion text, generation was truncated mid-sentence before closing the JSON string and braces. Groq's edge validator returned `json_validate_failed` (HTTP 400). Per the initial fallback rule, all unparseable responses defaulted to `"OFF-LOAD"` with `confidence = 0.0` and `risk_score = 100.0`. This artificially inflated the offload rates (88–95%) and caused high parse-failure counts across all systems.
* **Status of Run 1 Data:**
  Archived with suffix `_run1_truncated`. Performance numbers from Run 1 are strictly quarantined and invalidated.
* **Corrective Actions Implemented for Run 2:**
  1. `max_tokens` set to `4096` across all systems to provide ample headroom for full reasoning traces and comprehensive rationales.
  2. Fixed `reasoning_effort = "medium"` across all systems.
  3. Modified error handling protocol: A call that still fails to parse after retries is recorded as a missing value (`decision = None` / `"PARSE_FAILURE"`, `risk_score = None`, `is_parse_failure = True`) instead of defaulting to `"OFF-LOAD"`. Metrics will be reported both with failed profiles excluded and with failures counted as `"OFF-LOAD"`.
  4. Added concurrency to the runner respecting Groq paid-tier limits (1,000 RPM, 250k TPM).

### Deviation 2: Deletion of Unverified "Real-World" Case Vignettes
* **Date:** 2026-10-31
* **Relevant Commits:**
  - Creation commit: `8ece46f` (`feat(data): add 35 real-world case vignettes from superior courts and parliamentary inquiries with evaluation script`)
  - Quarantine commit: `f06c433` (`chore(data): quarantine unverified vignettes folder and document deviation in deviations_log.md`)
* **Summary Note:**
  Fabricated illustrative vignettes with a false provenance claim were committed and removed; no results from them are used.
* **Root Cause & Impact:**
  The 35 case vignettes were constructed without retrieving or fetching full-text primary court judgments, dockets, or official agency case files. While the high-level legal principles reflected published rulings (such as the Lahore High Court ruling in *Muhammad Abbas v. FIA* and the Sindh High Court ruling in *Jibran Nasir v. Federation of Pakistan*), the specific case dockets, names, and fine-grained feature values (`bank_funds_pkr`, `local_ties_score`, `document_authenticity_score`, exact profession, and travel history) were synthetically populated/interpolated rather than verbatim-extracted from primary legal texts.
* **Status of Data:**
  The directory `experiments/data/UNVERIFIED_vignettes/` and associated scripts (`evaluate_real_cases.py`, `generate_real_cases.py`) have been permanently deleted from the repository. All preliminary evaluation numbers generated by `evaluate_real_cases.py` are discarded, invalid, and will not be used in the thesis.
* **Corrective Policy Enforced:**
  1. No case may be recorded from memory or plausible interpolation.
  2. Any future real-world case vignette must be grounded strictly in retrieved, verifiable primary court judgments or official published records, with direct quotations and URLs provided.
  3. All non-reported profile fields must be marked strictly as `null` (not filled with plausible values).
  4. Real case vignettes are strictly qualitative benchmarks and will not be used for quantitative algorithmic scoring or model evaluation.
